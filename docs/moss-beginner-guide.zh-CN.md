##   _Moss 小白指南：  理解你的第一次 AI Agent 链上交易 _
 Moss 是一个面向 AI Agent 和 Monad 生态的开发框架，它帮助 AI Agent 更安全、更标准化地调用区块链能力。本指南帮助没有深入 Web3 和 AI Agent 背景的开发者理解：

1.  Moss 为什么存在？ 
2.  Moss 如何帮助 AI Agent 使用区块链？ 
3.  如何完成第一次 Moss 模拟交易？

 本指南不会从代码开始，而是从应用场景出发，帮助你理解 Moss 的设计目的，并完成你的第一次 Moss Demo 体验。



##  1. Moss 是什么？（What is Moss） 
### 1.1 从 AI 到 AI Agent
  在理解 Moss 之前，需要先理解 AI 和 AI Agent 的区别。传统 AI 主要负责理解信息和生成内容。例如，用户可以向 ChatGPT 提问，AI 会根据已有知识生成答案。

  AI Agent 则进一步扩展了 AI 的能力。AI Agent 可以理解用户目标，并通过调用外部工具完成连续任务。例如，一个旅行 AI Agent 不只是告诉用户有哪些航班，而是可以帮助查询航班、比较价格、整理行程，并通过连接相关服务完成预订流程。

  简单来说，传统 AI 更偏向“提供建议”，而 AI Agent 更偏向“执行任务”。

  Moss 是一个帮助 AI Agent 使用区块链功能的工具。如果你问AI如何把 MON 换成 USDC，AI知道怎么回答，但是不会真的操作。因为区块链操作像：让一个外国人去银行办理业务。他需要知道：银行地址表格格式、身份验证、操作流程。而Moss 就像：一个银行柜台工作人员，帮助 AI理解流程。但是不会替用户签字付款。

### 1.2 为什么普通 AI Agent 仍然无法直接操作区块链？
  虽然 AI Agent 已经具备调用工具的能力，但是区块链环境相比普通互联网应用更加复杂。例如，一个用户希望 AI 帮助完成一次资产兑换。表面上看，这只是简单的一句话：“帮我把 MON 换成 USDC。”但是在区块链内部，这个操作需要处理多个步骤：

+  找到支持兑换功能的区块链应用。 
+  确认正确的智能合约。 
+  生成符合规则的交易数据。 
+  检查交易是否能够成功执行。 
+  确保用户资产不会因为错误操作产生损失。 

  普通 AI Agent 可以理解用户想做什么，但是它通常缺少一套标准化、安全的方法去完成这些链上操作。这也是 Moss 存在的原因。

### 1.3 Moss 在 AI Agent 中扮演什么角色？
  Moss 并不是一个新的交易平台，也不是一个替代钱包的软件，它更像是 AI Agent 与区块链世界之间的连接层。普通 AI Agent 拥有理解能力，例如理解用户想进行兑换、转账或者查询余额，Moss 则提供执行这些任务所需要的区块链能力。当用户希望完成资产兑换时，Moss 可以帮助 AI Agent：

+  找到可用的兑换能力。 
+  调用对应的区块链 Protocol。 
+  生成交易。 
+  模拟交易结果。 

  但是 Moss 不会直接控制用户钱包，也不会替用户签署交易，最终的交易授权仍然由用户的钱包完成。



##  2. 为什么需要 Moss？（Why Moss exists） 
 理解 Moss，需要先了解几个基础概念。   

### 2.1 什么是 Blockchain（说给小白听）？
  区块链可以理解为一种由多个参与者共同维护的公开数据库，传统数据库通常由一个中心机构管理，例如银行管理用户账户余额，用户相信银行保存的数据，并通过银行系统完成交易。区块链则采用不同方式，它通过网络中的多个节点共同维护数据记录，任何参与者都可以验证记录是否真实。例如，一笔普通银行转账依赖银行系统确认；而区块链交易会被记录在公开网络中，并由整个网络验证。目前常见的区块链网络包括：

+  Monad  (⭐)
+  Ethereum 
+  Solana 
+  Polygon 

这些网络可以理解为不同的区块链基础设施，它们拥有不同的技术设计和生态应用。

### 2.2 什么是Monad？
  Monad 是一个**区块链网络**， 也是 Moss 当前支持的主要运行环境。

互联网中存在：

+  Google 的服务器系统。 
+  Amazon 的云计算系统。 
+  微信的服务系统。 

区块链世界中也存在不同网络：

+  Monad 提供 Monad 生态。
+  Ethereum 提供以太坊生态。 
+  Solana 提供 Solana 生态。 

  不同区块链网络拥有不同的性能、规则以及支持的应用，Moss 当前主要帮助 AI Agent 与 Monad 生态中的应用进行交互。

### 2.3 什么是 Protocol（协议）？
    Protocol 是理解 Moss 最重要的概念之一，在区块链中，Protocol 可以理解为运行在区块链上的应用服务。

传统互联网中，不同平台提供不同功能：

+  银行提供转账服务。 
+  交易平台提供资产兑换服务。 
+  电商平台提供商品交易服务。 

区块链中的 Protocol 也是类似的概念，不同 Protocol 负责不同功能。

#### 1.Swap Protocol（兑换协议）
主要负责不同资产之间的交换。用户拥有 MON，希望兑换 USDC。Swap Protocol 负责计算兑换价格，并完成资产交换。

#### 2.Lending Protocol（借贷协议）
主要负责资产借贷，用户可以存入资产获取收益，或者抵押资产借出其他资产。

#### 3.NFT Protocol
主要负责 NFT 的创建、查询以及转移。

  因此，Protocol 可以理解为区块链世界中的“功能服务提供者”，Moss 的作用不是创造这些 Protocol，而是帮助 AI Agent 理解：“完成某个任务时，应该调用哪个 Protocol，以及如何正确调用。”

### 2.3 什么是 Capability？
  Capability 可以理解为 AI Agent 可以使用的一种技能。

普通 AI 可能只具备语言理解能力。

例如：

+  阅读文本。 
+  回答问题。 
+  生成内容。 

通过 Moss，AI Agent 可以获得额外的区块链能力，例如：

+  查询余额。 
+  转账。 
+  兑换资产。 
+  查询 NFT 信息。 

因此，Capability 就像给 AI Agent 增加新的工具技能，Moss 的核心设计，就是将复杂的区块链操作封装成 AI Agent 可以调用的 Capability。

##  3. Moss 如何工作？  （How is work）
   Moss 的核心流程可以概括为：discover → load → action → simulate。这四个步骤描述了 AI Agent 从理解用户需求，到生成并验证区块链操作的完整过程，为了更好理解，我们使用一个实际案例：

“用户希望 AI 帮助完成一次资产兑换，将 1 MON 兑换成 USDC。”

  在传统 Web3 操作中，用户需要自己打开交易应用，选择兑换功能，输入资产数量，确认交易参数，最后通过钱包签名。Moss 的目标是让 AI Agent 能够理解用户需求，并协助完成这些复杂步骤，同时保证用户资产安全。

这里直接给案例帮助理解上述流程！^^

```abap
Alice 想让 AI 帮她兑换资产，Alice：帮我把 1 MON 换成 USDC。    
Step 1 ：Discover（发现能力）
AI 先问 Moss：“我现在有哪些事情可以做？”  Moss 返回：“你可以查询余额，转账，Swap兑换。” 
（类似打开手机查看有哪些 App 可以使用）

Step 2 ：Load（加载工具）
AI告诉Moss：“我要兑换。”   Moss：“加载Swap功能，然后找到哪个 Protocol 可以完成兑换。”
（例如找到这些协议帮助完成PancakeSwap或者Kuru）

Step 3 ：Action（生成操作）
AI准备：“我要：1 MON换USDC。” Moss：“生成一份交易计划。”
（注意这里没有真的花钱。类似银行工作人员帮你填写转账单，但是还没有提交。）

Step 4 ：Simulate（模拟）
Moss：“先检查如果执行，会发生什么？”
（例如会告诉 Alice预计消耗 1 MON，获得 xxx USD，手续费 xxx，如果失败则提前告诉用户。）
```

  下面详细讲解各个步骤帮你细致理解！

### 3.1 Discover（发现能力）
  Discover 的作用是让 AI Agent 了解当前有哪些区块链能力可以使用，在没有 Moss 的情况下，AI Agent 并不知道区块链生态中有哪些可调用功能。例如，用户提出：“帮我把 MON 换成 USDC。”

AI Agent 需要知道：

+  是否存在资产兑换功能。 
+  哪些 Protocol 支持兑换。 
+  当前应该使用什么能力完成任务。 

Moss 会通过 Capability 系统告诉 AI Agent 当前可用的功能，例如：

+  查询余额（balanceOf） 
+  转账（transfer） 
+  授权（approve） 
+  资产兑换（swap） 

这个过程类似于一个软件查看自己可以调用哪些工具。

---

### 3.2 Load（加载能力）
  当 AI Agent 确定用户需要资产兑换后，下一步是加载对应能力。例如用户需要完成：MON → USDC，这个任务需要调用 Swap Capability，Moss 会加载支持兑换功能的 Protocol，目前 Moss 支持多个 Protocol，例如：

+  Kuru 
+  PancakeSwap V2 / V3 

  这些 Protocol 都提供资产交换功能，但是实现方式可能不同。对于用户来说，他们只关心：“我想完成兑换。”而 Moss 负责处理：“应该调用哪个 Protocol，以及如何正确调用。”

---

### 3.3 Action（生成操作）
  Action 阶段负责根据用户需求生成具体的区块链操作，如果用户希望：“将 1 MON 兑换成 USDC。”Moss 会根据用户输入生成一笔未签名交易。当然这里生成交易并不代表交易已经执行。

  可以把它理解为填写了一份交易申请，比如你在银行转账过程中：填写收款人、金额和用途之后，转账申请已经准备完成，但是，在最终提交之前，还需要你亲自确认。Moss 中的 Action 阶段的过程就跟这个过程类似，它负责准备交易，而不是直接移动用户资产。

---

### 3.4 Simulate（模拟验证）
  Simulation 是 Moss 最重要的安全机制之一，在真正执行交易之前，Moss 会先模拟交易结果。模拟过程会检查：

+  交易是否能够成功执行。 
+  用户资产会如何变化。 
+  是否出现异常情况。 
+  最终结果是否符合预期。 

  继续用这个例子，假如用户希望兑换1 MON → USDC，模拟结果可能显示：

+  消耗 1 MON。 
+  获得对应数量的 USDC。 
+  支付一定 Gas 费用。 
+  交易可以成功执行。 

如果模拟发现：

+  交易失败。 
+  参数错误。 
+  合约执行异常。 

  Moss 会提前返回警告，而不是让用户直接提交交易。



##  4. 什么叫“不签名、不发送交易”？  
  这是 Moss 最重要的设计。

  Moss README 中有一句话：**Moss only builds and verifies unsigned transactions. It never signs and never sends. **Moss 可以帮助 AI Agent 准备交易，但是不会替用户完成最终授权，这是 Moss 安全设计的核心。 

  如果 AI Agent 直接控制用户钱包，会产生风险，你要知道AI可能因为理解错误，用户表达不清楚，外部攻击而导致执行错误交易。你要知道区块链交易一旦确认，无法撤销，因此，让 AI 直接拥有完整钱包权限并不是安全方案。而Moss是先生成交易，自己进行模拟检查之后，让用户钱包确认，自己决定签名。你可以理解为AI帮你写银行转账申请，省去最麻烦的过程之后，你只要确认信息点击付款按钮。

  Moss 将 AI 的能力和用户的钱包权限分离， AI Agent 负责理解用户需求，并生成交易方案。Moss 负责创建交易，验证交易，模拟执行结果。用户钱包负责最终确认，签署交易，广播交易。

 

##  5. 第一次运行 Moss  
  认识Moss之后，现在让我们运行Moss吧，运行 Moss 提供的 Demo，体验AI升级装备后如何生成一次模拟交易！^^ 接下来可以通过官方示例实际运行 Moss，观察它如何发现能力、生成未签名交易并模拟执行结果。Moss 目前仍处于未经审计的 Alpha 早期测试阶段。这些操作适合学习和开发测试，不应该直接用于生产资金。  

###   5.1 环境准备需要 _Node.js_ 运行环境 和 _pnpm_ 安装项目依赖的工具。
  Moss 是一个使用 TypeScript 和 Node.js 开发的项目。 

  Node.js 是运行项目代码的环境，可以把它理解成一台负责执行 JavaScript 和 TypeScript 程序的机器。

  pnpm 是项目依赖管理工具，Moss 并不是只由仓库中的代码组成，它还会使用许多外部软件包，pnpm 会按照项目配置自动下载和管理这些软件包。

运行以下命令：

```abap
#复制 Moss 项目到你的电脑
#git clone 表示从远程 GitHub 仓库下载一份完整的项目副本。下载完成后，电脑中会出现一个名为 moss 的文件夹。
git clone https://github.com/nishuzumi/moss

#进入项目文件夹
cd moss

#安装依赖（安装 Moss 运行需要的组件）
pnpm install

#构建项目（把源码转换成可以运行的版本）
pnpm build





```

###  5.2 运行 WMON Demo  
#### 第一条命令行：
```abap
#运行 Moss 官方提供的 wrap 示例
pnpm --filter @themoss/example-simple-flow wrap
```

这条命令不会配置钱包，也不会真正兑换资产。它只是运行仓库中的 `example-simple-flow` 示例，并选择其中的 `wrap` 操作。`--filter` 用于指定需要运行的工作区软件包。Moss 是一个包含多个软件包的项目，这里只运行官方准备的简单流程示例。最后的 `wrap` 用于告诉示例运行 MON 封装流程。

##### 运行后发生了什么？
  虽然终端中只输入了一条命令，Moss 内部仍然会执行完整流程。

  Moss 先通过 discover 发现当前已经注册的能力，再通过 load 加载 WMON 对应的 Protocol Package 协议软件包。

  随后，action 根据示例中的账户、数量和操作类型生成一笔未签名交易。最后，simulate 在 Monad 当前状态下模拟这笔交易，并检查它是否能够正常执行。

  整个过程只生成和验证交易，不会调用钱包签名，也不会把交易发送到 Monad 网络。

##### 了解MON 与 WMON 的区别
  MON 是 Monad 网络的原生资产。它直接属于 Monad 网络本身，主要用于支付网络手续费，也可以作为链上资产使用。

  WMON 是 Wrapped MON，也就是封装后的 MON。它与 MON 保持一比一的价值关系，但使用 ERC-20 同质化代币标准。

  之所以需要 WMON，是因为原生资产和 ERC-20 代币在智能合约中的调用方式并不完全相同。很多去中心化应用按照 ERC-20 的统一接口处理资产，却无法用完全相同的方式处理原生 MON。

  将 MON 封装成 WMON，相当于把原生资产转换成一种更容易被智能合约统一识别的格式。它不会让资产升值，也不是把 MON 换成另一种货币。

  可以把 MON 理解成纸质现金，把 WMON 理解成与这笔现金等值的储值卡余额。价值没有变化，但储值卡使用统一接口，因此更容易被各种自动化系统读取和操作。

  当 WMON 不再需要时，还可以通过 unwrap 解除封装，重新获得等量 MON。

#### 第二条命令行：
```abap
#运行 Moss 官方提供的 Kuru 示例
pnpm --filter @themoss/example-simple-flow swap
```

##### 运行后发生了什么？
 这条命令会运行一次 MON 到 USDC 的报价和交易模拟。

USDC 是一种与美元价值挂钩的稳定币。示例的目标不是实际购买 USDC，而是观察 Moss 如何帮助 Agent 准备一次兑换操作。

  Moss 会加载 Kuru 对应的 Protocol Package 协议软件包，获取兑换所需的合约地址、ABI 应用程序二进制接口和参数规则。随后，Moss 会向 Kuru 查询报价，并根据输入资产、输出资产、兑换数量和滑点设置生成未签名交易。

  滑点表示用户可以接受的实际兑换结果与预期报价之间的最大差异。链上价格可能在交易准备和执行之间发生变化，因此兑换操作通常需要设置滑点范围。

  生成交易后，Simulator 模拟器会在 Monad 当前状态下测试执行结果。模拟可以帮助确认交易是否会失败、资产可能如何变化，以及 Receipt 结果记录是否完整对应所有 Change 状态变化。即使模拟成功，交易也没有真正发送，示例只是证明这笔操作在当前链上状态下具有可执行性。

#### 第三条命令行：
```abap
#获取 ABI 的命令
pnpm fetch-abi 0x1b81D678ffb9C0263b24A97847620C99d213eB14 swapRouter02
```

 ABI 是 Application Binary Interface 的缩写，中文通常翻译为应用程序二进制接口。智能合约部署到区块链后，程序需要知道它提供哪些函数、每个函数需要哪些参数，以及返回结果采用什么格式，ABI 就是描述这些接口的结构化文件。

  可以把智能合约理解成一台只有按钮和接口的机器，ABI 相当于这台机器的操作面板说明书。没有 ABI，程序虽然知道合约地址，却不知道应该怎样正确调用其中的功能。这条命令中的长字符串是目标智能合约地址，`swapRouter02` 是保存 ABI 时使用的名称，运行该命令前需要配置 `MONADSCAN_API_KEY`。

  MonadScan 是 Monad 的区块链浏览器服务，API Key 应用程序接口密钥用于允许工具通过接口读取已经验证的合约信息。**这个步骤主要面向希望开发新 Protocol Package 协议软件包的贡献者**，只想运行 wrap 和 swap 示例的新手可以暂时跳过。

#### 第四行命令：
```abap
#离线测试命令
pnpm test:offline
```

  离线测试主要检查项目自身的逻辑但不依赖实时 Monad RPC 远程过程调用服务。

  RPC 是程序访问区块链节点的一种接口，运行需要读取真实链上状态的示例时，Moss 需要通过 RPC 与 Monad 节点通信，而离线测试则使用项目准备好的测试数据和模拟环境，它更适合检查代码修改是否破坏已有功能，也可以在网络连接不稳定时使用。

  对于第一次接触 Moss 的用户，运行离线测试可以确认项目是否正确安装和构建，如果测试通过，通常说明本地开发环境已经基本可用。

### 5.3  这些命令真正帮助你理解了什么？
  快速开始并不只是复制几条命令，`git clone` 让你获得 Moss 的完整代码仓库，`pnpm install` 准备项目依赖，`pnpm build` 构建多个 Moss 软件包。

wrap 示例展示 Moss 如何处理原生资产与标准化代币之间的封装操作。

swap 示例展示 Moss 如何调用具体协议完成报价、生成交易和模拟兑换。

fetch-abi 展示协议开发者如何获取智能合约接口信息。

test-offline 展示开源项目如何在不依赖实时区块链的情况下验证代码行为。

  完成这一章后，你应该能够理解 Moss 的快速开始不是配置一个自动交易机器人，也不是让 AI 获得钱包控制权，它是在本地运行 Moss 的官方示例，观察一笔链上操作如何经过能力发现、协议加载、交易生成和模拟验证。^^

##  6. Moss 项目结构（开发者视角）  
  Moss 采用模块化的项目结构，将核心规则、交易模拟、资产标准、协议接入和 AI Agent 连接功能分别放在不同的软件包中。这样的设计可以避免所有功能集中在同一个文件里，也方便开发者单独修改、测试或扩展某一个部分。

```plain
packages

├── core
├── simulator
├── erc
├── system
├── protocols
└── mcp-server
```

### 6.1 Core（核心模块）
`@themoss/core` 是 Moss 的核心模块，负责定义整个框架如何组织和验证区块链能力。

开发者可以将它理解为 Moss 的管理中心。其他模块提供具体功能，而 Core（核心模块）负责确认这些功能应该如何注册、接收哪些参数，以及产生的结果是否符合 Moss 的规则。

  Core（核心模块）主要管理 Registry（注册表）、Capability（能力）、参数规则、Capability Tree（能力树）和 Receipt（结果记录）验证。

  Registry（注册表）用于记录 Moss 当前安装了哪些协议和能力。AI Agent 需要执行某项任务时，可以通过 Registry（注册表）找到对应的功能。

  Capability Tree（能力树）用于表示一项操作中包含的多层步骤。某些区块链操作并不是单独一笔简单交易，而是由多个相关操作组成。能力树可以帮助 Moss 按照确定的顺序整理和验证这些操作。

### 6.2 Simulator（模拟器模块）
`@themoss/simulator` 负责在交易真正发送之前模拟执行过程。

  模拟器会读取 Monad 网络当前的真实状态，并预测某笔交易执行后可能产生的结果。它会检查交易是否成功、资产发生了哪些变化，以及模拟过程中是否出现警告。

  模拟器并不会真的移动用户资产。它更接近一次正式操作前的演练。开发者和 AI Agent 可以先查看演练结果，再决定这笔交易是否值得交给钱包签名。

  当一项任务包含多笔相关交易时，Simulator（模拟器模块）还会将前一笔模拟产生的状态变化传递给下一笔模拟，使整套结果更加接近真实执行过程。

### 6.3 ERC（通用资产模块）
`@themoss/erc` 负责支持常见的区块链资产标准。

  ERC（以太坊改进提案标准）规定了不同类型数字资产应该使用怎样的接口。Monad 与以太坊虚拟机兼容，因此也可以使用这些标准。

  Moss 当前支持的主要资产类型包括 ERC-20（同质化代币标准）、ERC-721（非同质化代币标准）和 ERC-1155（多类型代币标准）。

  ERC-20（同质化代币标准）通常用于普通代币。相同种类的每一枚代币价值和功能相同，例如 USDC。

ERC-721（非同质化代币标准）通常用于 NFT。每一个资产都有独立编号，可以代表不同的头像、收藏品或游戏道具。

  ERC-1155（多类型代币标准）可以在同一个合约中管理多种资产，适合游戏道具、门票和批量数字物品。

  通过 ERC（通用资产模块），Moss 可以为 AI Agent 提供余额查询、转账、授权、所有者查询和资产信息查询等常用能力。

### 6.4 System（系统模块）
`@themoss/system` 保存与 Monad 网络直接相关的运行环境、官方常量和系统级能力。

  这个模块负责告诉 Moss 当前连接的是哪条区块链网络，并提供 Monad 主网的基础配置。WMON 的 wrap（封装）和 unwrap（解除封装）能力也由这个模块提供。

  Core（核心模块）定义 Moss 的通用规则，System（系统模块）则补充 Monad 网络中的具体环境信息。两者结合后，Moss 才能知道应该在哪条网络上生成和模拟交易。

### 6.5 Protocol Packages（协议软件包）
`@themoss/protocol-*` 用于接入具体的区块链协议。

  不同协议拥有不同的合约地址、ABI（应用程序二进制接口）、参数格式和结果解析方式。Moss 不会把所有协议规则直接写进核心模块，而是为每个协议建立独立的软件包。

  例如，`@themoss/protocol-kuru` 负责 Kuru 的报价和资产兑换能力，`@themoss/protocol-pancakeswap` 负责 PancakeSwap V2 和 PancakeSwap V3 的资产兑换能力。

  这种设计让 Moss 具有较好的扩展性。开发者希望增加新的借贷协议、跨链协议或 NFT 市场时，可以新增一个 Protocol Package（协议软件包），而不需要大范围修改 Moss 的核心代码。

### 6.6 MCP Server（MCP 服务器）
`@themoss/mcp-server` 负责让支持 MCP（模型上下文协议）的 AI Agent 调用 Moss。

  MCP（模型上下文协议）可以理解为 AI 与外部工具之间的一种统一连接方式。它规定 AI 应该如何发现工具、传递参数和接收结果。

  Moss 的 MCP Server（MCP 服务器）只向 AI Agent 提供 discover（发现能力）、load（加载能力）、action（生成操作）和 simulate（模拟验证）四个主要工具。

  这意味着 AI Agent 不需要直接读取整个 Moss 代码仓库。它只需要按照统一接口提出请求，就可以获得 Moss 提供的区块链能力。

### 6.7 各模块如何共同完成一次交易模拟
  当 AI Agent 希望模拟一次 MON 到 USDC 的兑换时，MCP Server（MCP 服务器）首先接收 AI 的请求。Core（核心模块）随后从 Registry（注册表）中寻找支持兑换的协议和能力。

  Protocol Package（协议软件包）根据用户输入准备正确的合约地址、参数和交易数据。System（系统模块）提供 Monad 网络环境，Simulator（模拟器模块）在当前链上状态中测试这笔交易。

  模拟完成后，Core（核心模块）会检查 Receipt（结果记录）是否完整对应所有 Change（状态变化）。验证通过后，Moss 才会将可阅读的结果和警告返回给 AI Agent。

  整个过程中，Moss 只负责寻找能力、准备交易和验证结果。用户资产没有被转移，钱包也没有进行签名。

##  7. Moss 未来应用场景  
  Moss 当前支持的操作范围仍然有限，但它展示了一种重要的发展方向，AI Agent 可以理解自然语言需求，Moss 可以将这些需求转换成可验证的链上操作，钱包则保留最终授权权力。随着更多 Protocol Package（协议软件包）加入，Moss 未来可以应用在更加复杂的区块链产品中。

### 7.1 AI 钱包助手
  传统区块链钱包通常要求用户自己理解网络、代币、合约、授权和手续费。对于刚接触 Web3 的用户来说，一次简单操作也可能包含多个陌生步骤。

  接入 Moss 后，钱包可以增加自然语言交互能力。用户可以直接描述自己的目标，例如查询 Monad 资产、向某个地址转账，或者将 MON 兑换成 USDC。

  AI Agent 负责理解用户想完成什么，Moss 负责找到对应能力、生成未签名交易并模拟结果。钱包随后将交易内容展示给用户，由用户决定是否签名。

  这种钱包助手不会完全代替用户做决定，而是帮助用户减少查找协议、填写参数和检查结果的工作。它能够降低操作门槛，同时保留钱包原有的授权机制。

  未来的 AI 钱包助手还可以在交易确认前，将复杂的合约数据转换成更容易阅读的说明。用户看到的不再只是一串地址和十六进制数据，而是本次操作预计消耗多少资产、获得什么资产、使用哪个协议，以及是否存在警告。

### 7.2 AI DeFi Agent
  DeFi（去中心化金融）包含资产兑换、借贷、流动性提供和收益管理等功能。用户通常需要在多个协议之间比较价格、收益和风险，然后手动完成操作。

  AI DeFi Agent（AI 去中心化金融代理）可以帮助用户收集和分析这些信息。例如，用户希望将 MON 兑换成 USDC 时，Agent 可以查询不同协议的报价，并根据价格、滑点和预期结果提出方案。

  Moss 可以为这个 Agent 提供标准化的协议调用方式。Agent 不需要为 Kuru、PancakeSwap 或其他协议分别编写完全不同的操作流程，而是可以通过统一的 Capability（能力）完成发现、加载、生成和模拟。

  当 Moss 未来接入借贷、质押和流动性协议后，AI DeFi Agent（AI 去中心化金融代理）还可以协助完成更加复杂的任务，例如比较不同收益机会、模拟资金调整方案，或者提前检查多个连续操作是否能够成功。

  这类 Agent 仍然需要明确的安全边界。Moss 可以准备和验证操作，但风险判断、资金授权和最终签名仍然不应完全交给模型自动决定。

### 7.3 Web3 游戏 Agent
  在 Web3 游戏中，角色、装备、土地和其他游戏物品可以通过 NFT 或代币形式记录在区块链上。

  传统游戏中的 AI 角色只能按照游戏内部规则行动。如果游戏资产接入区块链，AI Agent 还需要理解如何查询资产、转移道具、使用代币和调用游戏合约。

  Moss 可以将这些操作封装成 Agent 能够调用的 Capability（能力）。例如，一个游戏 Agent 可以先查询自己拥有的装备，再模拟购买新道具所需的资产变化。玩家确认后，钱包才会签署实际交易。

  这种模式也可以用于玩家助手。玩家可以用自然语言查询角色拥有哪些链上物品、某件装备是否可以转移，或者一次购买会产生什么结果。

  如果未来 Moss 支持更多游戏协议，它可能成为游戏 AI 与链上资产系统之间的连接层，让 Agent 不只能够理解游戏环境，也能够在受控条件下处理链上物品。

### 7.4 开发者自动化工具
  开发者在接入区块链协议时，通常需要寻找合约地址、读取 ABI（应用程序二进制接口）、编写参数、发送测试交易并检查事件记录。

  Moss 将这些内容整理进 Protocol Package（协议软件包），能够减少不同项目重复处理相同工作的情况。

  未来开发者可以使用 AI Agent 快速查询某个协议提供哪些能力，生成调用示例，并在真实链上状态中模拟结果。开发者仍然需要审核代码和安全假设，但 Moss 可以缩短早期研究和测试阶段所需要的时间。

  对于协议维护者来说，提供一个 Moss Adapter（Moss 适配器）或 Protocol Package（协议软件包），也可能成为一种新的开发者接入方式。其他 Agent 可以通过统一接口发现并使用该协议，而不必重新理解全部底层实现。

##  8. 总结  
  Moss 解决的并不是如何让 AI 直接控制用户的钱包，而是如何让 AI Agent 在不掌握签名权的情况下理解和准备区块链操作。   

  普通 AI Agent 可以理解用户提出的自然语言需求，但它并不天然了解每个区块链协议的合约地址、ABI（应用程序二进制接口）、参数规则和交易结果。Moss 通过 Protocol Package（协议软件包）整理这些信息，再将具体操作封装成 Agent 可以调用的 Capability（能力）。

  discover（发现能力）、load（加载能力）、action（生成操作）和 simulate（模拟验证）组成了 Moss 的主要工作流程。这个流程让 AI Agent 先确认有哪些能力可以使用，再加载具体协议，生成未签名交易，并在正式执行前检查可能产生的结果。    

  Moss 将交易准备权和资金签名权分开。AI Agent 与 Moss 可以完成信息整理、交易构建和模拟验证，但最终签名仍然由用户的钱包负责。这种设计降低了 AI 直接接触用户资产所产生的风险。

  Moss 的另一项重要价值是统一不同协议的接入方式。不同区块链协议拥有不同的合约、参数和返回结果，而 Moss 通过模块化的协议软件包将这些差异封装起来。AI Agent 因此可以使用相对统一的方式调用不同协议。

  对于初次接触 Moss 的开发者来说，运行 wrap（封装）和 swap（兑换）示例的意义并不只是完成两条命令。更重要的是观察 Moss 如何发现能力、加载协议、生成交易、模拟结果，以及如何在整个过程中避免直接签名和发送交易。

  Moss 目前仍处于未经审计的 Alpha（早期测试）阶段，不适合直接用于生产资金。它现阶段更适合作为学习、实验和开发工具，用来探索 AI Agent 与区块链交互的安全方式。

  从长期角度看，AI Agent 想要从信息助手发展为能够执行链上任务的工具，必须同时解决协议调用、结果验证和钱包授权问题。Moss 提供了一种清晰的框架设计，让 AI 负责理解需求，让 Moss 负责构建与验证操作，让钱包保留最终决定权。

  这也是 Moss 最值得关注的地方。它不是试图取消用户确认，而是在 AI 与区块链之间建立一个更加标准化、可检查并且权限分离的执行层。
