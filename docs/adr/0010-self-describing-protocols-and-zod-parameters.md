# Protocol packages are self-describing and compose through injected dependencies

A Protocol package exports top-level self-describing `@Protocol` classes; the composition root supplies selected modules, and Registry registers their Protocol exports and recursively injects declared dependencies. Core owns framework contracts, simulator owns trace mechanics, Protocol packages own ABI semantics, Receipts, and protocol-exclusive deployments, `@themoss/erc` stays address-free, system owns the shared Monad Runtime and shared verified asset constants and rejects non-143 RPCs, and MCP server owns transport; dynamic addresses come from chain state and adding a Protocol changes only its package and composition root. Capability and Query inputs use `{ type, description }`, separating a reusable context-free Zod value contract from the field's purpose and exposing the generated JSON-safe schema through `load`.

Protocol classes compose through declared `protocols` dependencies and typed injected fields. A decorated Protocol cannot extend another decorated Protocol; Registry rejects that inheritance so Receipt-only instances never execute a parent Protocol's Runtime-injecting constructor.

A Protocol nests one of its own Capabilities the same way it nests a dependency's: through the injected `self` reference, typed as `SelfRef<T, Methods>` over a named subset of its own Capabilities. Registry injects `self` at construction through the same builder as declared dependencies, so a self-nested Capability node gets the same Zod parameter validation and the same `protocol + method` stamping, and Registry resolves its Receipt parser identically. Protocol packages never hand-assemble CapabilityNode structures. `self` carries Capabilities only: `Methods` is constrained to `CapabilityNames<T>`, so naming a Query or a Receipt parser is a compile-time error. The injected runtime surface exposes the Protocol's Capabilities alone. A Query reads state and a Receipt parser stays pure, so neither may nest a Capability; reaching for `self` from either fails with a named framework error instead of an undefined property. `self` is a reserved injected name: a contract or dependency key called `self` is rejected when the Protocol is declared. An initialized `self` field is rejected when Registry constructs the instance. `declare self` is the only valid form.

Protocol metadata may declare fixed Package address labels independently of Handles. Registry renders them as `Package(Title Cased Slug:localName)` and validates the combined payload inside the Core-owned wrapper as a 1–32 character safe name. The composition root supplies Trusted token labels through the explicit Registry constructor option, rendered as `Trusted(name)`; Registry never discovers them by scanning ordinary Protocol exports. Within one catalog or Protocol, addresses and case-insensitive names are both unique.
